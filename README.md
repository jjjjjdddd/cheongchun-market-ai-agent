# 청춘마켓 안심거래 도우미

등록된 중고상품 데이터를 검색해 가격 판단에 필요한 정보와 거래 전 확인사항을 안내하는 개인 프로젝트입니다.

대학생 중고거래 서비스 **청춘마켓**을 개발한 뒤 상품을 찾는 것만으로는 가격과 거래 조건을 판단하기 어렵다는 점에서 시작했습니다. Python과 RAG를 이용해 상품 데이터를 검색하고 검색된 정보를 근거로 답변하도록 만들었습니다.

**제가 중점적으로 개선한 부분은 질문과 다른 제품의 정보가 답변 근거로 사용되는 문제였습니다.** 등록되지 않은 에어팟 프로 2 질문에 갤럭시 버즈2가 검색되는 사례를 확인했습니다. 제품군 검증과 검색 결과 필터링을 추가해 해당 질문에는 다른 제품 정보를 사용하지 않고 데이터 부족 안내를 제공하도록 바꿨습니다.

## 프로젝트 개요와 담당 범위

- 기간: 2026.08
- 형태: 개인 프로젝트
- 담당: 문제 정의부터 상품 데이터 구성과 화면 구현 및 기능 테스트
- 직접 수행한 개선: 등록 제품군 확인과 검색 결과 검증 및 데이터 없음 예외 처리
- 개발 방식: AI 개발 도구로 코드 구조를 학습했고 로컬 실행 환경 설정과 기능 테스트 및 검증 로직 개선은 직접 수행했습니다.

배경이 된 [청춘마켓 팀 프로젝트 자료](https://github.com/jjjjjdddd/portfolio)는 별도 저장소에 있습니다. 이 저장소는 이후 개인적으로 만든 거래 정보 안내 서비스입니다.

## 해결하려고 한 문제

사용자는 상품 가격뿐 아니라 상태와 출시 연도 및 구성품을 함께 고려해야 합니다. 저는 이 정보를 CSV로 정리하고 사용자 질문과 관련된 상품을 찾아 안내하도록 구성했습니다.

초기에는 벡터 검색 결과를 그대로 답변 근거로 사용했습니다. 같은 이어폰 카테고리라도 에어팟과 갤럭시 버즈는 다른 제품입니다. 검색이 실행되더라도 질문에 맞는 정보인지 확인하는 절차가 필요했습니다.

## 오매칭 사례와 개선

| 확인한 내용 | 수정 전 | 수정 후 |
|---|---|---|
| 질문 | CSV에 없는 에어팟 프로 2 | 같은 미등록 상품 질문 |
| 검색 근거 | 같은 이어폰 카테고리의 갤럭시 버즈2가 검색됨 | 등록 제품군과 일치하지 않으면 빈 검색 결과 반환 |
| 답변 처리 | 다른 제품의 정보가 가격 안내 근거가 될 수 있음 | 데이터 부족 안내와 추가 확인 항목 제공 |
| LLM 호출 | 검색 근거를 전달해 답변을 생성하는 구조 | 근거가 없으면 LLM을 호출하지 않음 |

다음 두 단계로 검증을 추가했습니다.

1. 질문에서 공백을 제거한 뒤 등록 제품군이 포함됐는지 확인합니다.
2. 벡터 검색 결과에서도 같은 제품군의 문서만 남깁니다.

현재 `app.py`에는 아이패드와 맥북 및 갤럭시버즈와 닌텐도스위치의 4개 제품군을 지정했습니다. 근거가 비어 있으면 `generate` 단계는 고정된 데이터 부족 안내를 반환합니다. 이 분기에서는 `ChatOllama`를 호출하지 않습니다.

이 결과는 특정 오매칭 사례를 개선한 경험입니다. 전체 검색 정확도나 오류 감소율을 측정한 수치는 아닙니다.

## 주요 기능

- CSV 상품 데이터를 문서로 변환하고 Chroma Vector DB에 저장
- 사용자 질문에 관련된 상품 문서 검색
- 질문의 제품군과 검색 결과의 제품군 확인
- Ollama 로컬 LLM을 이용한 데이터 기반 거래 안내
- 답변에 사용한 상품 정보를 화면에서 확인
- 상품 근거가 없는 경우 모델명과 상태 및 구성품 등 추가 확인 항목 안내
- 빈 질문 입력 시 안내 표시

## 데이터 구성

`data/products.csv`에는 현재 5개의 데모 상품 레코드가 있습니다. 4개 제품군으로 구성했으며 아이패드에는 상태가 다른 2개 레코드가 있습니다.

| 항목 | 컬럼명 | 용도 |
|---|---|---|
| 상품명 | `product_name` | 질문 대상과 검색 결과 비교 |
| 카테고리 | `category` | 상품 종류 확인 |
| 상태 | `condition` | 상품 상태 확인 |
| 출시 연도 | `year` | 가격 판단 조건 확인 |
| 정가 | `original_price` | 참고 정보 |
| 판매희망가 | `asking_price` | 등록 상품의 제시 가격 |
| 참고 시세 범위 | `market_range` | 데모 데이터에 기재한 비교 범위 |
| 거래 지역 | `location` | 거래 조건 확인 |
| 특이사항 | `note` | 구성품과 상품 상태 등 추가 정보 |

데이터의 가격과 시세 범위는 데모에 사용하는 등록 값입니다. 실시간 시장 가격이나 실제 거래 안전성을 검증한 정보는 아닙니다.

## 처리 흐름

| 순서 | 처리 |
|---|---|
| 1 | Streamlit 화면에서 사용자 질문 입력 |
| 2 | 등록 제품군 포함 여부 확인 |
| 3 | 등록 제품군이면 Chroma에서 관련 문서 최대 3개 검색 |
| 4 | 같은 제품군의 문서만 근거로 사용 |
| 5 | 근거가 있으면 Ollama로 거래 안내 생성 |
| 6 | 근거가 없으면 LLM 호출 없이 데이터 부족 안내 반환 |
| 7 | 답변과 사용한 상품 정보 표시 |

LangGraph의 `retrieve`와 `generate` 노드로 검색과 답변 생성을 연결했습니다. 현재 구현은 정해진 순서로 동작하는 RAG 워크플로입니다.

## 실행 방법

Python 3과 [Ollama](https://ollama.com/download)가 필요합니다. 모델 다운로드와 패키지 설치에는 인터넷 연결이 필요하며 Ollama가 실행 중이어야 합니다.

### 1. 저장소 받기

```bash
git clone https://github.com/jjjjjdddd/cheongchun-market-ai-agent.git
cd cheongchun-market-ai-agent
```

### 2. 가상환경과 패키지 설치

아래는 macOS와 Linux 기준입니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 3. 사용할 모델 준비

```bash
ollama pull qwen2.5:3b
ollama pull nomic-embed-text
```

Ollama가 실행되지 않았다면 앱을 실행하거나 별도 터미널에서 `ollama serve`를 실행합니다.

### 4. 앱 실행

```bash
python -m streamlit run app.py
```

터미널에 표시되는 로컬 주소로 접속합니다. 기본 주소는 `http://localhost:8501`입니다.

처음 실행하면 CSV 문서를 임베딩하고 벡터 저장소를 구성합니다. 준비 시간과 답변 속도는 실행 환경에 따라 달라집니다.

## 확인할 수 있는 입력 사례

| 입력 | 확인할 동작 |
|---|---|
| 아이패드 9세대 64GB를 28만원에 사도 될까요? | 같은 제품군의 상품을 검색하고 답변과 근거 표시 |
| 맥북 에어 M1을 살 때 확인할 점은 무엇인가요? | 등록된 상품 정보를 근거로 확인사항 안내 |
| 에어팟 프로 2의 가격을 알려줘 | 데이터 부족 안내와 추가 확인 항목 표시 |
| 공백만 입력 | 질문 입력 안내 표시 |

등록 상품의 답변 문구는 모델 실행 결과에 따라 달라질 수 있습니다. 데이터 부족 안내는 코드에서 정한 고정 문구입니다.

## 현재 한계와 다음 개선

- 제품군 목록을 코드에 직접 지정했습니다. 다음에는 CSV와 목록을 함께 관리하도록 개선하고 싶습니다.
- 제품군 단위의 문자열 검사이므로 세대와 용량 및 전체 제품명을 정확히 구분하지 못합니다.
- 데모 데이터 5개를 사용합니다. 실제 상품 등록 데이터와 연결하지 않았습니다.
- 모델 답변이 데이터만 사용하도록 프롬프트를 구성했지만 모든 부정확한 답변을 막는다고 보장할 수는 없습니다.
- 자동화된 테스트와 정확도 평가 체계는 아직 추가하지 않았습니다. 질문별 근거와 응답 결과를 비교하는 검증 사례를 늘릴 계획입니다.

## 프로젝트를 통해 배운 점

검색 결과가 나오는 것과 질문에 맞는 근거가 나오는 것은 다를 수 있다는 점을 직접 확인했습니다. 질문 대상과 등록 데이터가 일치하는지 확인하고 근거가 없는 상황에서는 안내 방식도 바꿔야 했습니다.

앞으로 자료를 분석하거나 AI 적용 사례를 검토할 때도 필요한 데이터와 적용 조건을 먼저 확인하는 방식으로 이 경험을 활용하고 싶습니다.
